# Сигурност: какво е направено и как е проверено

Обхват: администрацията (`/admin`), публичното API (`/api/public`), качването на снимки, базата и публикуването. Проверено на **2026-11-19** на локалния сайт. „Проверено“ означава, че има автоматичен тест (`cms/test/*.test.mjs` – 40 теста; `tools/qa/e2e-*.mjs` – в браузър) или команда, която може да се повтори.

## Удостоверяване и сесии

| Изискване | Реализация | Проверка |
|---|---|---|
| Без вградени пароли | първият администратор се създава само с `cli create-owner`; паролата се въвежда скрито (или през променлива за автоматизация) и не се отпечатва | ръчно + `auth.test` |
| Argon2id | `@node-rs/argon2`, 19 MiB, 2 итерации; минимум 12 знака; не съдържа имейла | `auth.test` |
| Сървърни сесии | в базата се пази SHA-256 на бисквитката, не самата стойност; абсолютно 12 ч., бездействие 2 ч. | `auth.test` (изтичане) |
| Бисквитка | `HttpOnly`, `SameSite=Strict`, `Secure` + префикс `__Host-` при HTTPS (`CMS_COOKIE_SECURE=auto`) | `e2e-1` B5–B6 |
| Ротация на сесията | нова сесия при вход и след втори фактор; старата се унищожава | код `routes/auth.mjs` |
| Изход | унищожава сесията в базата | `e2e-1`, `e2e-2` |
| CSRF | токен на сесия във всяка заявка за промяна (`x-csrf-token` / `_csrf`) + проверка на `Origin` и `Sec-Fetch-Site`; формата за вход – двойна бисквитка | `e2e-1` B7–B9 |
| Ограничаване на входа | 5 неуспеха/15 мин. → заключване 15 мин., удвоява се до 1 ч.; по IP хеш **и** по имейл; еднакво време за непознат имейл | `auth.test`, `e2e-2` L1–L2 |
| Втори фактор | TOTP (RFC 6238, проверен с вектора от стандарта), еднократни кодове за възстановяване (пазят се хеширани), един и същ код не се приема повторно | `auth.test` |
| Одит | журнал на входове, промени, публикуване, модерация (без тайни; IP само като хеш) | страница „Настройки“ |
| Авторизация на всяко API | middleware на `/admin/*`: сесия + втори фактор + CSRF; скритите бутони не са защита | `e2e-1` A1–A6: 16 API заявки и 11 страници без сесия са отказани |

## Качване на снимки (OWASP File Upload)

| Мярка | Реализация | Проверка |
|---|---|---|
| Само за влезли | общата защита на `/admin/api/*` | `e2e-1` A3 |
| Тип по съдържание | подпис на файла (JPEG/PNG/WebP/AVIF); HEIC се отказва ясно; несъответствие с `sharp` → отказ | `media.test` |
| Ограничения | 25 MB/файл, 30 файла и 150 MB наведнъж, 150 снимки/рецепта, общо 4 GB оригинали | `media.test` |
| Decompression bomb | `limitInputPixels` 50 Мпикс; прекалено големи се отказват | `media.test` |
| Безопасни имена | `u<време>-<хеш>.webp`; оригиналното име се чисти и се пази само като метаданна; пътят от името никога не се ползва | `media.test` |
| Обход на пътя | `slug`/`file` се валидират с регулярен израз; `trashPhoto`, `thumbnail` отказват `..` | `media.test` |
| Метаданни | публикуваният WebP е без EXIF/GPS/ICC (проверено с тайна стойност в EXIF); крайният сайт – 0 файла с метаданни (`check-images`) | `media.test`, сглобяване |
| Неизпълнимо | файловете са данни (WebP); оригиналите са в `/data/originals` (0600), извън уеб папката; услугата сервира само умалени копия през удостоверени пътища | `media.test` |
| Повредени файлове | отказ с ясно съобщение, без срив | `media.test`, `e2e-1` C4 |
| Публикува се само след успех | файлът се пише в `photos/` чак след валидиране и обработка | `media.test` |
| Дубликати | SHA-256 на оригинала; подобни кадри (dHash) → предупреждение | `media.test`, `e2e-1` C7 |

Посетителите **не** могат да качват снимки в тази версия.

## Публично API

JSON-only (`415` при друго), проверка на `Origin` (чужд → `403`), лимит на тялото 16 KB, валидиране на всяко поле, параметризирани SQL заявки, ограничаване на честотата, honeypot; HTML от посетители никога не се вгражда (само `textContent`). Подробности – `RATINGS_COMMENTS_DESIGN.md`. Проверено: `e2e-1` D10–D13, E4–E8; `community.test`.

## Заглавия и политика за съдържание

- Администрацията: `Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self'; style-src-attr 'unsafe-inline'; img-src 'self' data: blob:; connect-src 'self'; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'`, `Cache-Control: no-store`, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`. Няма вградени скриптове. `style-src-attr 'unsafe-inline'` е нужен за няколко вградени атрибута `style` (не позволява изпълнение на код).
- Публичният сайт: както преди (CSP чрез `<meta>` със сигурни хешове на Astro; `frame-ancestors` от Caddy). Новите скриптове са външни модули `'self'`.
- Порт 8080 е вързан към `127.0.0.1`; услугата „cms“ не е публикувана на хоста.

## Данни

База извън Git и извън публичната папка (том); тайният ключ на инсталацията (`/data/secret.key`, 0600) – само в тома и в пълното резервно копие. TOTP тайните са шифровани (AES-256-GCM). IP адресите не се пазят – само HMAC. Имейлът на коментатор е по желание и не се публикува.

## Известни ограничения (не са решени)

1. **Гост-идентичността не е самоличност** – виж `RATINGS_COMMENTS_DESIGN.md`. Оценките могат да се манипулират чрез изчистване на бисквитки; ограничаването по IP хеш ги забавя, но не ги спира.
2. **Няма защита срещу ботове в продукция** (Turnstile е само подготвен от страна на сървъра).
3. **Няма HTTPS локално**; поведението на `Secure`/`__Host-` бисквитки е проверено само по логика и в код, не в браузър през HTTPS.
4. **Администраторът е един** (роля `owner`); няма отделни права.
5. **Услугата е root-free (`USER node`)**, но `node:sqlite` е с отбелязан „експериментален“ статус в Node 22 – следете за промени при надграждане.
6. **Откриване на подобни/дублирани снимки** е евристика (dHash), не гаранция.
7. **Прегледът на чернова** не е идентичен с публичната страница.
8. Не е правен външен тест за проникване и не е пускан `npm audit` върху новите зависимости.
