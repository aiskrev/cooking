# Профили на посетителите и общност

Документът описва профилите на посетителите: вход, профил, любими, „Сготвих“, оценки, коментари и модерация. Добавени са през ноември 2026 г.

Архитектурата не е сменена:

- **Сайтът** остава статичен (Astro). Новите страници също са статични и зареждат данните си с JavaScript от `/api/…`.
- **Сървърната част** е същата Node услуга `cms/` (Hono + `node:sqlite`) зад същия Caddy.
- **Маршрутизиране:** не са нужни нови маршрути в Caddy, защото всичко минава през съществуващия `/api/*`.

## Какво има

| Функция | Гост | Влязъл (непотвърден имейл) | Влязъл (потвърден имейл) |
|---|---|---|---|
| Четене, търсене, филтри, режим „готвене“, порции, печат | ✓ | ✓ | ✓ |
| Любими | в браузъра (`localStorage`) | в профила | в профила |
| Списък за пазаруване | в браузъра | в браузъра | в браузъра |
| „Сготвих“ (история) | – (покана за вход) | ✓ | ✓ |
| Оценка 1–5 | – | – (покана за потвърждаване) | ✓ |
| Коментар (едно ниво отговори), редакция и изтриване на собствен | – | – | ✓ |
| Сигнал за коментар (с категория) | – | ✓ | ✓ |

Публичните профили не са част от първата версия.

Ролите са `user`, `moderator` и `admin`. Гостът не е роля в базата.

- **Модератор:** чакащи коментари, коментари със сигнали, скрити и отхвърлени. Може да одобрява, отхвърля и скрива с причина, да отхвърля сигнали и да вижда история.
- **Администратор:** всичко на модератора, плюс профили (роля и статус) и журнал.
- **Първият администратор** се задава от командния ред:
  ```
  cms/cli.mjs set-role --email=… --role=admin
  ```
- **Собственикът в `/admin`** (отделен вход с TOTP) продължава да модерира, както досега.

## Страници

| Страница | BG | EN |
|---|---|---|
| Вход | `/bg/vhod/` | `/en/sign-in/` |
| Регистрация | `/bg/registratsia/` | `/en/register/` |
| Забравена парола | `/bg/zabravena-parola/` | `/en/forgot-password/` |
| Нова парола | `/bg/nova-parola/#token=…` | `/en/reset-password/#token=…` |
| Потвърждаване на имейл | `/bg/potvarzhdenie/#token=…` | `/en/verify-email/#token=…` |
| Профил | `/bg/profil/` | `/en/account/` |
| Модерация | `/bg/moderatsia/` | `/en/moderation/` |
| Поверителност и правила | `/bg/poveritelnost/` | `/en/privacy/` |

Всички освен „Поверителност“ са `noindex` и не влизат в `sitemap`. Списъкът с тях е `privateRoutes` в `src/i18n/index.ts` и `PRIVATE` в `astro.config.mjs`.

Кодът от писмата е след `#`, така че не стига до сървъра при отваряне на страницата и не попада в журналите на Caddy. Страницата го изчиства от адресната лента веднага.

Заглавката е такава:

- **Гост:** вижда „Вход“, който води до `?next=<текущата страница>`.
- **Влязъл:** вижда бутон с инициала и името си. Менюто се отваря с `aria-expanded`, затваря се с Escape и с клик извън него, а фокусът се връща към бутона.
- **Гостите не правят заявки за профил.** Бисквитката-подсказка `mstate=1` казва на страниците, че има вход. Без нея `src/scripts/account.ts` не пита сървъра.

## API

Всички отговори са JSON и `Cache-Control: no-store`. Съобщенията се превеждат на английски по заглавката `x-site-language: en` (`cms/lib/i18n.mjs`).

**`/api/account/*`** (`cms/routes/account.mjs`):

| Метод и път | Достъп |
|---|---|
| `GET me` | всеки; връща потребител, CSRF токен и брой сесии |
| `POST register`, `verify`, `login`, `forgot`, `reset` | без вход; същият произход и JSON |
| `POST logout`, `verify/resend`, `password`, `sessions/revoke-others`, `delete` | вход + CSRF |
| `PATCH profile` | вход + CSRF |
| `GET export` | вход; JSON файл за изтегляне |
| `GET favorites` · `PUT/DELETE favorites/:slug` · `POST favorites/merge` | вход (+ CSRF за промени) |
| `GET cooked` · `POST recipes/:slug/cooked` · `PATCH/DELETE cooked/:id` | вход (+ CSRF) |
| `GET ratings` · `PUT/DELETE recipes/:slug/rating` | вход (+ CSRF); оценката изисква потвърден имейл |
| `GET comments` · `POST recipes/:slug/comments` · `PATCH/DELETE comments/:id` · `POST comments/:id/report` | вход (+ CSRF); коментарът изисква потвърден имейл |

**`/api/mod/*`** (`cms/routes/mod.mjs`). Ролята се проверява на сървъра при всяка заявка.

| Метод и път | Роля |
|---|---|
| `GET comments?view=pending\|reported\|hidden\|all&page=` | модератор |
| `GET comments/:id/history` | модератор |
| `POST comments/:id/action {action: approve\|reject\|hide\|restore\|dismiss, reason}` | модератор |
| `GET users?q=&page=` · `PATCH users/:id {role, status, reason}` · `GET audit?page=` | администратор |

**`/api/public/*`.** Четенето е същото, но `GET recipes/:slug/community` вече връща `me` (влязъл ли е посетителят, потвърден ли е, любима ли е рецептата).

Старите заявки на гости за запис (`POST …/rating`, `…/comments`, `…/cooked`, `comments/:id/report`) връщат 401 с покана за вход.

## Данни и миграция

Миграцията е `cms/migrations/002_accounts.sql`. Прилага се автоматично при пускане на услугата, както 001. Само добавя: нищо не се изтрива и съществуващите данни не се променят.

| Таблица / колона | Ключове и индекси |
|---|---|
| `users` (email, `email_verified_at`, `display_name`, Argon2id хеш, роля, статус, език, дати) | `UNIQUE(email COLLATE NOCASE)`, CHECK за роля, статус и език |
| `user_sessions` (SHA-256 на бисквитката, CSRF токен, изтичане, хеш на IP, User-Agent) | FK → `users ON DELETE CASCADE`; индекси по `user_id` и `expires_at` |
| `user_tokens` (verify/reset, SHA-256 на кода, изтичане, `used_at`) | `UNIQUE(token_hash)`; FK cascade |
| `favorites` | `PRIMARY KEY(user_id, recipe_slug)` = UNIQUE(userId, recipeId); индекс по рецепта |
| `cook_events` (`cooked_at`, порции 1–48, бележка ≤ 500) | индекси `(user_id, cooked_at DESC)`, `(recipe_slug, user_id)` |
| `ratings.user_id` | частичен `UNIQUE(user_id, recipe_slug) WHERE user_id IS NOT NULL`; плюс старото `UNIQUE(recipe_slug, actor_id)` с `actor_id = 'u:<id>'` |
| `comments.user_id`, `comments.edited_at` | индекс `(user_id, created_at DESC)` |
| `comment_reports.category`, `reporter_user_id` | CHECK на категорията; индекс на отворените сигнали |
| `moderation_events.moderator_user_id` | индекс по време |

**Старите данни от гости:**

- **Оценки** с `user_id NULL` остават и се броят в средната. Нови гост-оценки не се приемат.
- **Коментари** от гости остават видими.
- **Отметки `cooked_marks`** се добавят към броя „сготвена от N читатели“, който е отделен от личната история.

**Средната оценка** се смята винаги от таблицата (`GROUP BY`), без кеширан агрегат, така че паралелни заявки не могат да я развалят. Записът на оценка е една атомарна заявка `INSERT … ON CONFLICT DO UPDATE`.

**Връщане назад:**

1. Преди внедряване направете резервно копие:
   ```
   cms/cli.mjs backup
   ```
2. При проблем е най-сигурно да възстановите копието:
   ```
   cms/cli.mjs restore <папка> --force
   ```
   Старият образ на услугата игнорира новите таблици и колони, така че връщането само на кода също е безопасно.
3. Ръчно премахване (без загуба на старите данни):
   ```sql
   DROP TABLE favorites; DROP TABLE cook_events; DROP TABLE user_tokens; DROP TABLE user_sessions;
   DROP INDEX ux_ratings_user_recipe; DROP INDEX idx_comments_user; DROP INDEX idx_reports_open; DROP INDEX idx_moderation_at;
   ALTER TABLE moderation_events DROP COLUMN moderator_user_id;
   ALTER TABLE comment_reports DROP COLUMN reporter_user_id; ALTER TABLE comment_reports DROP COLUMN category;
   ALTER TABLE comments DROP COLUMN edited_at; ALTER TABLE comments DROP COLUMN user_id;
   ALTER TABLE ratings DROP COLUMN user_id;
   DROP TABLE users; DELETE FROM schema_migrations WHERE version = 2;
   ```
   Изтриват се и оценките и коментарите от профили. Първо изнесете данните (`exportData`).

## Сигурност

**Пароли.**

- Хешират се с Argon2id (`@node-rs/argon2`, същите настройки като за администратора).
- Изискват поне 12 знака, най-много 200, без имейла в паролата.
- Собствена криптография няма. Случайните кодове са от `crypto.randomBytes`, а сравненията са с постоянно време.

**Сесии.**

- **Бисквитка:** `__Host-msid` при HTTPS (`msid` локално). Тя е HttpOnly, Secure и SameSite=Lax. В базата се пази само SHA-256 на стойността.
- **Срок:** сесията изтича след 14 дни без активност и най-късно след 30 дни.
- **Нова сесия:** издава се при всеки вход, за да няма фиксиране на сесия.
- **Прекратяване:**

  | Събитие | Какво се прекратява |
  |---|---|
  | Нова парола по писмо | всички сесии |
  | Смяна на паролата | всички сесии; текущото устройство получава нова |
  | Смяна на ролята | всички сесии на профила |
  | Спиране на профила | всички сесии на профила |
  | Изтриване на профила | всички сесии на профила |

**CSRF.** Всяко действие на влязъл потребител изисква три неща:

- заглавката `x-csrf-token`, която съвпада с токена на сесията;
- същия произход (`Origin` / `Sec-Fetch-Site`);
- `Content-Type: application/json`. Обикновена HTML форма от чужд сайт получава 415.

Изходът също изисква токена.

**Без разкриване на регистрирани адреси.**

- **Регистрация:** отговорът винаги е 202 със същия текст. Ако адресът вече има профил, собственикът му получава писмо „вече имате профил“.
- **Забравена парола:** отговорът винаги е 202.
- **Вход:** грешна парола и непознат имейл дават едно и също съобщение. При непознат имейл се прави фиктивна Argon2 проверка, за да се изравни времето.

**Ограничаване на опитите** (таблиците `login_attempts` и `rate_events`):

| Действие | Ограничение |
|---|---|
| Вход | 5 неуспеха → заключване за 15 мин, удвоява се до 1 ч (по IP и по имейл) |
| Регистрация | 5 на час от IP и 3 на ден за имейл |
| Забравена парола | 5 на час от IP и 3 на час за профил (тихо) |
| Нова парола | 10 на час от IP |
| Повторно писмо за потвърждение | 3 на час |
| Коментари | 3 за 10 мин и 10 на ден на профил, 30 на ден от IP |
| Оценки | 60 на час |
| Сигнали | 10 на час |
| „Сготвих“ | 30 на час |

**Против спам.**

- Коментират само влезли с потвърден имейл.
- Скрито поле-капан за ботове.
- Откриване на повторен текст за 24 часа.
- Без връзки в коментарите.
- Всички нови и редактирани коментари минават през одобрение, така че подмяна след одобрение не е възможна.
- Блокиран от собственика автор (`blocked_actors`) не може да коментира и оценява.
- CAPTCHA не е добавена (няма измерен проблем). Turnstile за старата гост-форма вече не се използва.

**Без IDOR.** Чужд запис („Сготвих“, коментар) връща 404, все едно не съществува. Всички заявки съдържат `user_id = ?` от сесията.

**XSS.**

- Текстът от посетители се пази без промяна и се показва само с `textContent`; никъде не се ползва `innerHTML` с данни от потребители.
- CSP на страниците е от Astro (хешове на скриптовете).

**Отворено пренасочване.** `?next=` приема само относителен адрес `/bg/…` или `/en/…` от същия сайт.

**Масово присвояване.** Сървърът чете само изброени полета. Ролята и статусът се сменят само от администратор (не и собствените) или от командния ред.

**Журнали.** Не се записват пароли, кодове от писмата и стойности на сесии. Грешките при изпращане на писмо се записват само с кода на грешката.

## Писма

Писмата се изпращат през SMTP с `nodemailer` 10.4.0. Това е единствената нова зависимост; `npm audit` за продукционните зависимости показва 0 уязвимости.

Настройва се с променливи на средата (`docker-compose.prod.yml` → `/opt/recipes/.env`, никога в Git):

| Променлива | Стойност |
|---|---|
| `MAIL_TRANSPORT` | `smtp` |
| `MAIL_FROM` | адрес на подателя |
| `MAIL_SMTP_HOST` | сървър |
| `MAIL_SMTP_PORT` | 587 (STARTTLS, задължителен) или 465 |
| `MAIL_SMTP_SECURE` | `1` при порт 465 |
| `MAIL_SMTP_USER`, `MAIL_SMTP_PASS` | вход в SMTP |

Без настроен SMTP (`MAIL_TRANSPORT=disabled`, по подразбиране в продукция) регистрацията и „забравена парола“ връщат 503 „временно не е налично“. Вход за вече създадени профили работи.

Локално (`docker-compose.yml`) е `MAIL_TRANSPORT=outbox`: писмата са JSON файлове в `/data/outbox` на тома `cms-data`. Те съдържат еднократни кодове и се използват само за локални проверки.

## Поверителност

Страницата е `/bg/poveritelnost/`. Описва само реално пазените данни. Не се събират телефон, адрес, дата на раждане и други ненужни данни.

**Срокове:**

| Данни | Срок |
|---|---|
| Сесии | 14 дни без активност / 30 дни най-много |
| Кодове от писмата | изтриват се 7 дни след използване или изтичане |
| `rate_events` | 48 ч |
| Журнал `audit_events` | 12 месеца |

Почистването е в `purgeMembers` и `purgeExpired` и се пуска на всеки 10 минути.

**Изтриване на профил** (изисква паролата):

- Изтриват се профилът, сесиите, кодовете, любимите, историята и оценките.
- Одобрените коментари се **анонимизират**: авторът става „Изтрит профил“, а връзката с профила, IP хешът и `actor_id` се премахват. Всички други коментари се изтриват по съдържание.
- **Това е решение по подразбиране и собственикът трябва да го потвърди.** Алтернативата е пълно изтриване и на одобрените коментари.

**Износ на данни:** `Моят профил → Настройки → Изтегли данните си` дава JSON без хеша на паролата.
