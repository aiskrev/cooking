Дата: **2026-11-20**. Хранилище: `aiskrev/cooking`, основен клон `main` (последен комит при одита: `eac79c8`). Всички числа са от реална проверка на файловете и на публичния сайт.

## 1. Текуща архитектура

| Част | Как е устроена |
|---|---|
| Публичен сайт | Astro 7.4.12, `output: 'static'`, `trailingSlash: 'always'`, `build.format: 'directory'`; Markdown рецепти като Content Collection (`src/content.config.ts`) |
| Търсене | Pagefind 1.6 (индекс се прави върху сглобените HTML страници) |
| Администрация / API | Hono + Node 22 (`cms/`), SQLite (`node:sqlite`): потребители, сесии, ревизии, публикуване, медия, оценки, коментари, журнал |
| Публикуване | `cms/lib/publish.mjs`: сглобява в `/app/.build/<версия>`, проверява, копира в `/releases/<версия>`, включва с атомарна смяна на символичната връзка `current`; връщане назад = смяна на връзката |
| Сървиране | Caddy в контейнера (`deploy/Caddyfile.prod`): статични файлове от `/srv/current`, `/admin` и `/api` към услугата; пред него Caddy на хоста (TLS, Cloudflare) блокира `/admin` отвън |

## 5. Зависимости

- **Медия:** снимките са по `<рецепта>/photos/<файл>`; `manifest.json` пази произхода. Всичко се реферира по име на файл и стабилен идентификатор → преводът **не дублира и не преименува** снимки.
- **Стабилен идентификатор (slug):** оценки, коментари, „Сготвих“ (SQLite), любими и списък за пазаруване (localStorage), ревизии, медия, кошче.
- **SEO:** canonical, Open Graph, schema.org `Recipe`/`WebSite`/`BreadcrumbList`, sitemap (`@astrojs/sitemap`), RSS, `robots.txt` (всичко е `noindex`, докато не се зададе `INDEXABLE=1`).
- **Администрация:** `contentHash` (само `index.md` + снимки), `scanLiveSlugs` (само `recepti/`), `normalize`/`validate`/`serialize`, ревизии (`recipe_revisions.action` – свободен текст), `vocabulary`, преименуване на таксономия, преглед (`views/preview.mjs`).

## 6. Рискове за съвместимост и как са посрочени

| Риск | Решение |
|---|---|
| Стари адреси (`/recepti/...`) и споделени връзки | постоянно пренасочване 301 в Caddy към `/bg/...` със запазена заявка; резервна страница в корена |
| Оценки/коментари да не се разцепят | ключът остава slug; страниците и на двата езика викат същия API |
| Любими и списък за пазаруване да не се губят при смяна на езика | пазят се по slug; списъкът записва редовете и на двата езика; старият формат се чете и се показва |
| Колекция с английски файлове да не чупи сглобяването | отделна колекция `recipesEn` със същия идентификатор; чернови на превод не се публикуват |
| `contentHash`/публикуване да не пропуснат английска промяна | хешът включва `index.en.md`; манифестът пази езиците на всяка рецепта |
| Нови стойности (етикет/категория) без превод | речник на таксономията (`src/i18n/taxonomy.json` + допълнение `_taxonomy.json`), блокиращо публикуването на превода |

## 7. Подход (приет)

Един общ набор от изгледи (`src/views/`), тънки обвивки по език (`/bg/…`, `/en/…`), централен модул `src/i18n/`, превод като `index.en.md` до оригинала, общи снимки и числа, стабилна таксономия по ключ (българската стойност), език „от адреса“ (без автоматично пренасочване по браузър), превод в администрацията, проверки и документация. Виж `I18N_ARCHITECTURE.md`.
