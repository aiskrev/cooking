# Модерна българска кухня и Мишлен щрих – кулинарен блог (статичен)
*Modern Bulgarian Cuisine with a Michelin Touch*

Статичен сайт с рецепти и много снимки. Построен с [Astro](https://astro.build): всяка рецепта е папка с текст (`index.md`) и снимки; при сборката снимките се оптимизират автоматично, а резултатът е обикновени файлове (HTML/CSS/снимки). Публичният сайт е статичен; администрацията, оценките и коментарите са отделна локална услуга (виж по-долу).

> Това е **отделен проект**, не е свързан с A.I. Commerce Studio. Сайтът се ползва **само локално**; нищо не е разгръщано.
> Хранилището в GitHub (`aiskrev/cooking`) е **публично** и съдържа кода и всички 73 рецепти (и английския им превод) със снимките и манифестите им. Снимките са генерирани с изкуствен интелект и са маркирани като илюстративни, а текстовете са реконструкции, които чакат проверка (`review: true`). Описанията за импорта (`_private-imports/`), отчетите (`reports/`) и заглавните снимки на сайта (`src/assets/site/`) остават само локално.
> Името е **примерно** – сменя се в `src/site.config.ts`.

Всички команди работят през Docker (на компютъра не са нужни Node, npm или Python).

## Двуезичност: български и английски

Сайтът е на два езика: **български** (оригиналът, `/bg/…`) и **английски** (пълен превод, `/en/…`). Всяка рецепта е папка с `index.md` (български) и `index.en.md` (превод); **снимките са общи**. Адресите, оценките, коментарите, любимите и списъкът за пазаруване са по един и същи идентификатор на рецептата, така че смяната на езика не губи нищо. Старите адреси (`/recepti/…`) се пренасочват с 301 към `/bg/…`.

```bash
npm run translations:report    # състояние на превода на всяка рецепта
npm run translations:check     # проверка (влиза и в npm run check)
npm run translations:export -- --only <рецепта>
npm run translations:generate -- --dry-run
```

Преводът се редактира и в администрацията (табове „Български | English“ при всяка рецепта). Документация: `docs/I18N_ARCHITECTURE.md` (как работи), `docs/TRANSLATION_WORKFLOW.md` (как се превежда и публикува), `docs/I18N_DEPLOYMENT.md` (пускане и връщане назад), `docs/TRANSLATION_QA_REPORT.md` (какво е проверено), `docs/I18N_AUDIT.md` (одит преди промяната).

## Администрация, оценки и коментари (локално)

Освен статичния сайт има малка Node услуга (`cms/`) със SQLite, достъпна на **http://localhost:8080/admin** (само от този компютър): вход с парола, табло, редактор на рецепти с качване и подреждане на снимки, чернови и ревизии, публикуване на нова версия на сайта със сигурно връщане назад, оценки и коментари от посетителите с модерация. Публичните страници остават статични – оценките и коментарите се зареждат от API.

```bash
docker compose up -d --build cms web
docker compose exec -it cms node --disable-warning=ExperimentalWarning cms/cli.mjs create-owner --email=вие@пример.bg
```

Документация: `docs/ADMIN_ARCHITECTURE.md` (как работи), `docs/RECIPE_EDITOR_GUIDE_BG.md` (ръководство за редактора), `docs/RATINGS_COMMENTS_DESIGN.md`, `docs/DATABASE_MIGRATIONS.md`, `docs/LOCAL_RUNBOOK.md` (пускане, резервни копия, преди публично пускане), `docs/SECURITY_VALIDATION.md`, `docs/QA_RESULTS.md`.

## 0. Внасяне на рецепти и снимки от `D:\Cooking`

Изходната папка се чете **само за четене** – нищо там не се мести, трие или презаписва.

1. **Инвентар** (SHA-256, размери, дубликати, перцептивен хеш, партиди по време):

   ```powershell
   docker build -t recipes-import tools/import
   docker run --rm -v D:\Cooking:/src:ro -v D:\Projects\recipes\reports\_work:/out -v D:\Projects\recipes\tools\import:/t/scripts:ro recipes-import node /t/scripts/scan.mjs /src /out/inventory.json
   docker run --rm -v D:\Cooking:/src:ro -v D:\Projects\recipes\reports\_work:/out -v D:\Projects\recipes\tools\import:/t/scripts:ro recipes-import node /t/scripts/sheets.mjs /src /out/inventory.json /out/sheets
   ```

   Контактните листове (`reports/_work/sheets/`) са за визуален преглед: на всеки кадър има номер `#N`.
2. **Описание на рецептите** – в `_private-imports/source-recipes/*.mjs` (лично, не се качва): заглавие, текст, съставки, стъпки и към всяка стъпка номер на снимка `ph: N`.
3. **Импорт** (идемпотентен – повторното пускане не дублира; ръчно редактиран `index.md` не се презаписва, а се записва `index.generated.md`):

   ```powershell
   docker run --rm -v D:\Cooking:/src:ro -v D:\Projects\recipes:/work -v D:\Projects\recipes\tools\import\run.sh:/run.sh:ro recipes-import sh /run.sh import-recipes.mjs --dry-run
   docker run --rm -v D:\Cooking:/src:ro -v D:\Projects\recipes:/work -v D:\Projects\recipes\tools\import\run.sh:/run.sh:ro recipes-import sh /run.sh import-recipes.mjs
   ```

   За всяка внесена снимка в `src/content/recipes/<рецепта>/manifest.json` се пази оригиналното име, SHA-256, размер и роля. Копията са WebP до 1600 px без метаданни.
4. **Отчети** – `reports/ASSET_INVENTORY.md`, `RECIPE_INVENTORY.md`, `MISSING_ASSETS.md`, `IMAGE_RECOGNITION_REVIEW.md`, `IMPORT_REPORT.md` (копие и в `D:\Cooking\reports`).

### Какво има на страницата на рецептата
- Фото-история до 10 кадъра по реда на готвенето, увеличаване на цял екран (клавиатура, плъзгане, подписи).
- Съставки с отметки, **преоразмеряване на порциите** (само числовите количества; „на вкус“, времето и температурата не се пипат), копиране и **списък за пазаруване** (`/spisak/`, пази се само в браузъра).
- **Режим „готвене“** – голям текст, стъпка по стъпка, таймер за стъпките с време, списък със съставки, екранът не заспива (където браузърът позволява). Работи без интернет.
- Техника, контрол на температурата, съвети, чести грешки, заместители, поднасяне, съхранение, редакционна индикация за алергени.
- Състояние на текста („шеф-реконструкция – чака проверка“) и бележка „Илюстративни снимки“.

## 1. Бърз преглед на сайта

```bash
docker compose up -d --build web
```

Отворете <http://localhost:8080> (пренасочва към `/bg/`; английската версия е на `/en/`). Така се вижда сайтът точно както ще е в продукция (сглобен, с търсене). Спиране:

```bash
docker compose down
```

За редактиране с автоматично опресняване (без търсене, то се създава само при сглобяване):

```bash
docker compose up dev
```

Отворете <http://localhost:4321>. Първото стартиране е по-бавно (инсталира зависимостите).

## 2. Как да добавя нова рецепта със снимки

1. **Създайте папката на рецептата** (име на латиница се прави автоматично от заглавието):

   ```bash
   docker compose run --rm dev npm run new-recipe -- "Заглавие на рецептата"
   ```

   Получава се `src/content/recipes/<име-на-рецептата>/` с `index.md` (шаблон) и празна папка `photos/`.

2. **Копирайте ВСИЧКИТЕ снимки наведнъж** в `photos/` на рецептата (JPG, PNG, WebP или AVIF; оригиналите от телефон/фотоапарат са наред – не е нужно да ги смалявате). Редът им е по азбучен ред на имената, затова ги именувайте с номера: `01-съставки.jpg`, `02-нарязване.jpg`, … (по-добре на латиница, без интервали).
   - Снимки от iPhone във формат HEIC първо преобразувайте в JPG.

3. **Генерирайте списък на снимките** за описанията им:

   ```bash
   docker compose run --rm dev npm run new-recipe -- --photos <име-на-рецептата>
   ```

   Копирайте отпечатания блок `photos:` в `index.md` и за всяка снимка попълнете:
   - `alt` – кратко описание на това, което се вижда (за незрящи и за Google). **Задължително за добър резултат.**
   - `caption` – подпис, който се показва под снимката и в увеличения изглед (по желание).

4. **Попълнете `index.md`** (полетата са обяснени по-долу). За всяка стъпка в `steps:` може да посочите `photo: 03-име.jpg` – снимката се показва под стъпката и става част от галерията „стъпка по стъпка“.
   Снимки, които не са прикачени към стъпка, се показват автоматично в секцията **„Още снимки“**.

5. **Проверете и сглобете:**

   ```bash
   docker compose up -d --build web
   ```

   Ако липсва файл, посочен в `index.md`, сглобяването спира с ясно съобщение. Снимки без `alt` описание се показват с общ текст и сборката ги изброява в предупреждение.

6. Когато текстът е проверен: сменете `review: true` на `false` (бележката „Чернова“ изчезва).

### Полета в `index.md`

| Поле | Значение |
|---|---|
| `title`, `description` | Заглавие; кратко описание (до 200 знака) за Google и споделяне |
| `date` | Дата на публикуване (ГГГГ-ММ-ДД); подрежда рецептите |
| `review` | `true` = чернова, показва се бележка „чака проверка“ и рецептата не влиза в RSS |
| `illustrative` | `true` = показва се бележка „Илюстративни снимки“ (за генерирани снимки). С ваши снимки – `false` |
| `category` | Една категория, напр. `Основни ястия` (страница `/kategorii/...`) |
| `tags` | Списък етикети (страници `/etiketi/...`) |
| `prepTime`, `cookTime` | Минути; общото време се смята само |
| `servings` | Брой порции |
| `difficulty` | По желание: `лесна`, `средна`, `сложна` |
| `cover` | Главна снимка (име на файл). Ако липсва – първата по азбучен ред |
| `photos` | `alt` и `caption` по име на файл |
| `ingredients` | Групи съставки: `title` (по желание) и `items` |
| `steps` | Стъпки: `title` (по желание), `text`, `photo` (по желание) |
| текст под `---` | Бележки/съвети (Markdown) |

Пример има в `src/content/recipes/pylneni-chushki-s-kayma-i-oriz/index.md`.

## 3. Какво прави сборката със снимките

- От всяка снимка се правят варианти **AVIF, WebP и резервен JPEG** в няколко ширини (360–1600 px, никога по-големи от оригинала) – браузърът взима най-подходящия (`srcset` + `sizes`).
- Всяка `<img>` има **`width` и `height`** (без скачане на страницата) и **цветен размазан заместител** до зареждане.
- Всички снимки са `loading="lazy"`, освен главната на рецептата (тя е с висок приоритет).
- **Оригиналите не се обслужват**: те остават в `src/` и не влизат в `dist/`. Сглобените файлове нямат **EXIF/GPS** метаданни (потвърдено с проверка – виж `docs/QA-REPORT.md`).
- Увеличаване по клик/докосване: стрелки (клавиатура и бутони), `Esc`, плъзгане с пръст, подписи, брояч. Без JavaScript връзката отваря оптимизираната снимка.
- Оптимизираните снимки се кешират между сборките; първата сборка с много големи снимки е бавна (AVIF), следващите – бързи.

## 4. Сглобяване, проверки, настройки

Публичният адрес се задава при сборка (използва се за канонични връзки, `sitemap.xml`, RSS, Open Graph):

```bash
SITE_URL=https://recepti.вашдомейн.bg docker compose up -d --build web
```

(в PowerShell: `$env:SITE_URL="https://..."; docker compose up -d --build web`)

- По подразбиране сайтът е **неиндексируем** (`robots.txt` забранява всичко + `noindex`). `INDEXABLE=1` го прави индексируем – само при бъдещо публикуване.
- Автоматични проверки (счупени връзки, `schema.org/Recipe`, снимки, EXIF) – падат при грешка:

  ```bash
  docker build --target check -t recipes-check .
  ```

- Проверки в истински браузър (екранни снимки на 360/390/768/1024/1440 px, лайтбокс, търсене, достъпност с axe) и Lighthouse:

  ```bash
  docker compose --profile qa run --rm qa node shots.mjs
  docker compose --profile qa run --rm -e RUNS=3 qa node lighthouse.mjs
  ```

  Резултатите са в `qa-output/` (не се записват в git). Последно измерените числа са в `docs/QA-REPORT.md`.

Основни настройки: `src/site.config.ts` (име, автор, текст за „Илюстративни снимки“).

## 5. Публикуване на VPS (след изрично одобрение)

> Нищо от този раздел не е изпълнявано. Публикуването е отделно решение на собственика.

Препоръка: на същия Hetzner сървър като **отделен проект и отделен домейн/поддомейн** (напр. `recepti.вашдомейн.bg`), със собствена папка и собствен блок в Caddyfile; без връзка с базата и Compose проекта на бизнес сайта.

1. **DNS:** A запис на поддомейна към IP на сървъра.
2. **Сборка на компютъра** (с реалния адрес):

   ```bash
   docker build --target export --build-arg SITE_URL=https://recepti.вашдомейн.bg --output type=local,dest=release .
   ```

   В `release/` са готовите файлове. (Добавете `--build-arg INDEXABLE=1` само когато сайтът трябва да се индексира.)
3. **Папка на сървъра** (еднократно): `/srv/recipes/releases/` и символна връзка `/srv/recipes/current`.
4. **Качване на нова версия** (атомарно – посетителите никога не виждат наполовина качен сайт):

   ```bash
   REL=$(date +%Y%m%d-%H%M%S)
   scp -r release/. потребител@сървър:/srv/recipes/releases/$REL/
   ssh потребител@сървър "ln -sfn /srv/recipes/releases/$REL /srv/recipes/current"
   # по желание: оставете последните 3 версии
   ssh потребител@сървър "cd /srv/recipes/releases && ls -1t | tail -n +4 | xargs -r rm -rf"
   ```

5. **Caddy:** добавете блока от `deploy/Caddyfile.snippet` (сменете домейна) и презаредете Caddy. Блокът задава:
   - кеш за година (`immutable`) за `/_astro/*` (снимки и CSS с хеш в името), 30 дни за шрифтове, 1 час за индекса на търсенето и **без кеш (проверка с ETag)** за HTML – нова рецепта се вижда веднага;
   - сигурни заглавки (HSTS, `nosniff`, `X-Frame-Options`, `frame-ancestors`, `Referrer-Policy`, `Permissions-Policy`);
   - компресия и собствена страница 404.

   Ако Caddy работи в Docker, папката `/srv/recipes` трябва да е монтирана в контейнера само за четене (`/srv/recipes:/srv/recipes:ro`) – това е промяна в Compose файла на прокси-то и се прави внимателно, отделно от другите проекти.

   Политиката за съдържанието (Content-Security-Policy: само собствени скриптове/шрифтове/снимки) е вградена в HTML страниците с хешове на скриптовете, затова не се дублира в Caddy.
6. **Алтернатива без промяна на монтирането:** самостоятелен контейнер със сайта (`docker build --target serve -t recipes .`, пуска се на порт 8080 в мрежата на Caddy) и в Caddyfile `reverse_proxy recipes:8080`.
7. **Архив:** добавете `/srv/recipes/releases/` към нощния архив (или само последната версия). **Важно:** на сървъра има само оптимизирани снимки. **Оригиналите са само в папката `src/content/recipes/*/photos/` на този проект** – пазете копие на проекта (частно git хранилище с Git LFS, външен диск или облак). Git без LFS не е подходящ за стотици големи снимки.
8. **Проверка след публикуване:** отворете сайта, рецептата, `/robots.txt`, `/sitemap-index.xml`, `/rss.xml`; пуснете адреса в [Rich Results Test](https://search.google.com/test/rich-results) на Google (работи само с публичен адрес).

## 7. Бележки

- **Поверителност:** без бисквитки, без анализ, без външни шрифтове и скриптове. Единственото, което се пази в браузъра, е изборът на тъмна/светла тема (`localStorage`).
- **Търсене:** [Pagefind](https://pagefind.app) – индексът се създава при сглобяване и търсенето работи изцяло в браузъра. В режим `dev` търсене няма.
- **Печат:** бутонът „Отпечатай рецептата“ дава чист изглед (заглавие, време, съставки, стъпки, без менюта и снимки на стъпките).
- **Език:** само български. Добавянето на английски означава втори набор рецепти и преводи на интерфейса – не е направено.
- **Много рецепти:** списъкът `/recepti/` е на една страница; при стотици рецепти е нужно разделяне на страници.
- **Шрифт:** Lora (SIL OFL 1.1), хостван на самия сайт – `public/fonts/README.txt`.
